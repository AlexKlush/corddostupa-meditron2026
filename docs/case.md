# Кейс «Третьего мнения» и БФТ: конспект

Источник: `Кейс_Третье_мнение.pdf` (выдан на хакатоне Meditron 2026) и БФТ НПКЦ ДиТ ДЗМ к результатам работы ИИ-сервисов (версия от 15.09.2026, https://mosmed.ai/documents/349/%D0%91%D0%A4%D0%A2_15.09.2026_1.pdf). Здесь только то, что нужно для работы; полные документы читать в оригинале.

## Кейс: сервис персонального плана дальнейшего обращения пациента на основе ИИ-анализа

**Кейсодатель.** «Третье Мнение»: системы поддержки принятия врачебных решений и продукты для управления качеством медпомощи.

**Проблема.** Пациент проходит КТ, маммографию или рентгенографию, у него находят патологию, но он не записывается к врачу. Без автоматической маршрутизации он прерывает лечение, откладывает визит или уходит в другую клинику. ИИ уже помогает интерпретировать исследования, но ценность для клиники в том, чтобы результат анализа приводил к следующему действию: повторному приёму, консультации другого специалиста или дополнительному исследованию.

**Два сценария.**
- **B2B, внутренний контур клиники.** Сервис анализирует заключения и данные пациента и показывает администратору или врачу возможные следующие шаги; сотрудник видит рекомендацию в рабочем интерфейсе и вовремя предлагает запись.
- **B2C, внешний контур.** Рекомендация показывается пациенту в приложении или личном кабинете: понятное объяснение маршрута и возможность сразу записаться.

**Бизнес-эффект.** Расширение продуктовой линейки, больше сценариев для существующих ИИ-сервисов, рост конверсии в повторный приём и последующие услуги.

**Ожидается.** ML-сервис, который получает заключение ИИ по КТ / РГ / ММГ и определяет дальнейший маршрут; обоснование подхода и почему он поднимет конверсию; схема интеграции в контур клиники (сайт, приложение, внутренняя платформа, МИС/РИС).

**Аудитория.** Клиники и сети; администраторы, операторы контакт-центра, координаторы лечения; врачи; пациенты.

**Ограничения и риски.** Риск медицинской ошибки; нужна медицинская валидация; разный стиль заключений; защита персональных и медицинских данных; за короткий срок не обучить и не внедрить промышленное решение.

**Критерии оценки.**
- Соответствие ожиданиям: корректное использование ML; сервис получает заключение ИИ и формирует следующий шаг; релевантность рекомендаций; бизнес-ценность для «Третьего мнения»; реальный пользовательский сценарий, архитектура и ожидаемый эффект.
- Техническая реализуемость: данные из МИС/РИС или через API (для демо допустимы тестовые данные и имитация интеграции); безопасность: сервис **не ставит диагноз**, а использует заключение ИИ для навигации и поддержки сотрудника.

## БФТ: что важно для нас

Организаторы просили читать только три блока: поля Kafka-сообщения, требования к разделам «Описание» и «Заключение» DICOM SR и шаблоны текстового описания ИИ. Остальное необязательно.

### Kafka-message (приложение 3, общие поля)

| Ключ | Что это |
|---|---|
| `studyIUID` | уникальный номер исследования |
| `aiResult.seriesIUID` | номер дополнительной серии от ИИ |
| `pathologyFlag` | `true` / `false`: есть ли признаки патологии |
| `confidenceLevel` | вероятность патологии во всём исследовании, целое 0–100 |
| `modelId`, `modelVersion` | номер модели и версия сервиса |
| `report` | текст «Описание» |
| `conclusion` | текст «Заключение» |
| `dateTimeParams.*` | `downloadStartDT`, `downloadEndDT`, `processStartDT`, `processEndDT` (ISO 8601) |
| `norma` | 1 = исследование без патологии, 0 = с патологией (сценарий автосортировки) |

Плюс поля по клиническим задачам, например `ct_emphysema_conf_level`, `ct_chest_aai_pulm_nodule_solid_right`, `ct_lymphadenopathy_size`, `mmg_rads_right`, `mmg_rads_left`, `mmg_acr_right`, `dx_infiltration`-подобные классы для рентгенографии. В Kafka вероятность 0–100, в DICOM SR и доп. серии 0,00–1,00.

### Структура DICOM SR (раздел 3.3, порядок полей менять нельзя)

1. Модальность; 2. область исследования; 3. идентификатор исследования (Study UID в ЕРИС ЕМИАС); 4. дата и время формирования заключения ИИ;
5. предупреждения: «Заключение подготовлено программным обеспечением с применением технологий искусственного интеллекта» и «В исследовательских целях» (без РУ Росздравнадзора) либо «…медицинским изделием…» и «Для поддержки принятия врачебных решений» (с РУ);
6. наименование, версия и назначение сервиса; 7. технические данные (толщина и количество срезов); 8. технологические дефекты;
9. **описание**: находки с размерами и характеристиками по шаблону приложения 11;
10. **заключение**: обобщение находок в синдром или диагноз либо текст об отсутствии патологии;
11. руководство пользователя (цвет разметки, обозначения, классификации).

В SR комплексного сервиса обязательна вероятность по каждому виду патологии с отметкой превышения порога.

### Шаблоны (приложение 11), которые используем в демо

- **КТ ОГК (11.1).** Лёгочная ткань: очаг(и), инфильтрация/консолидация, ателектаз/фиброз, интерстициальные изменения, эмфизема, кальцинаты; описание правого и левого лёгкого (локализация, характер, размеры); трахея и бронхи; плевральные полости (гидроторакс, пневмоторакс); средостение (лимфоаденопатия ВГЛУ); сердце и крупные сосуды (кальциноз коронарных артерий, аневризма/дилатация аорты); костные структуры (переломы, компрессионный перелом позвонка); надпочечники; щитовидная железа. Заключение: дифференциальный ряд; по умолчанию «Патологических изменений органов грудной клетки не выявлено». Опционально «Рекомендации» и «Дообследование».
- **Маммография (11.2).** Качество по PGMI; по каждой железе: плотность по ACR (A–D), кожа, кальцинаты доброкачественные и подозрительные (квадрант, распределение), образования (квадрант), нарушение архитектоники, аксиллярные лимфоузлы. Заключение: BI-RADS 1–5 отдельно для правой и левой железы.
- **Рентгенография ОГК (11.4)** и **околоносовых пазух (11.3)**, суставов и позвоночника (11.5–11.14): похожая структура «поле → возможные значения → описание → заключение».
