# Журнал решений

Сюда записываем решения, которые не очевидны из кода: выбор технологий, форматы, отказ от подходов, договорённости между участниками. Цель: чтобы никто (включая Claude на другой машине) не обсуждал одно и то же дважды.

## Правила

- Записи только **добавляются в конец** файла. Старые не редактируются: если решение изменилось, пишем новую запись со ссылкой на старую (`Отменяет: ...`).
- Запись делается в том же коммите, что и изменение, к которому она относится.
- Дата в формате `ГГГГ-ММ-ДД`. В поле «Кто» GitHub-логин (или имя) того, кто принял/записал решение.
- Если при пуше конфликт из-за одновременных записей, оставить обе.

## Шаблон записи

```markdown
### ГГГГ-ММ-ДД. Короткий заголовок решения
- **Кто:** @login
- **Статус:** принято | предложено | отменено
- **Контекст:** какая была проблема или вопрос.
- **Решение:** что решили.
- **Почему / альтернативы:** что ещё рассматривали и почему не выбрали.
- **Последствия:** что теперь нужно делать или чего нельзя делать.
```

### 2026-10-03. Совместная работа с нескольких компьютеров и аккаунтов
- **Кто:** @AlexKlush
- **Статус:** принято
- **Контекст:** над проектом работают несколько человек с разных машин и под разными GitHub-аккаунтами. Сессии Claude Code на разных машинах не разделяют историю чата.
- **Решение:** единственный общий источник контекста: этот репозиторий. Правила работы зафиксированы в `CLAUDE.md`, решения ведутся здесь. Участники с правами write коммитят в `main`.
- **Почему / альтернативы:** общий чат между машинами технически невозможен. Вариант «все только через PR» надёжнее против конфликтов, но тяжелее для небольшой команды; оставлен как правило для крупных и рискованных изменений.
- **Последствия:** перед каждым пушем `git pull --rebase --autostash origin main`; `--force` в `main` запрещён; секреты и тяжёлые данные в репозиторий не попадают. Если конфликты станут частыми, пересмотреть в пользу веток и PR.

### 2026-10-03. Журнал всех запросов с каждой машины в `docs/log/`
- **Кто:** @AlexKlush
- **Статус:** принято
- **Контекст:** нужно, чтобы сохранялись все просьбы пользователей с обоих компьютеров и что по ним изменено; сессии Claude на разных машинах не видят чужой чат.
- **Решение:** hook `UserPromptSubmit` (`scripts/log_prompt.py`, подключён в `.claude/settings.json`) дословно дописывает каждый запрос в `docs/log/ГГГГ-ММ-ДД_<git-user>_<машина>.md`; Claude после задачи дописывает под запросом `**Сделано:**`. Файл коммитится вместе с работой.
- **Почему / альтернативы:** положиться на то, что Claude сам запишет запрос, ненадёжно. Один файл на человека+машину+день исключает конфликты слияния. Один общий файл или файл на запись отвергнуты: первый конфликтует, второй даёт сотни мелких файлов. Токены (`ghp_`, `sk-`, `AKIA`, приватные ключи) маскируются автоматически.
- **Последствия:** перед пушем нужен `--autostash` (hook оставляет незакоммиченный файл). Запросы пишутся дословно, поэтому в чат нельзя вставлять секреты. Нужен `python3` на каждой машине.

### 2026-10-03. Прототип кабинетов: статический HTML, затем обёртка Streamlit
- **Кто:** @LeshaKl (Алексей)
- **Статус:** принято
- **Контекст:** нужно быстро показать, как выглядят кабинет администратора и кабинет пациента; бэкенд, Kafka, шифрование и серверы пока откладываем.
- **Решение:** одностраничный прототип на чистых HTML/CSS/JS (без фреймворка и сборщика) в `prototype/`, открывается на localhost; та же страница встраивается в Streamlit ради публичной ссылки. «ИИ» имитируется на демо-данных, оформленных по БФТ (DICOM SR, поля Kafka).
- **Почему / альтернативы:** React/Vite дал бы компоненты, но добавил бы сборку и node_modules ради прототипа; Streamlit-виджеты не дают нужной анимации, поэтому Streamlit только оборачивает готовую страницу.
- **Последствия:** демо-данные лежат в JS-модуле прототипа; когда появится ML-сервис, заменить имитацию на вызовы API. Все люди и цифры в прототипе вымышленные и так подписаны.

### 2026-10-03. Айдентика и визуальное направление прототипа

Палитра светлая медицинская: фон #F7FAFA, карточки #FFFFFF, акцент #0FA3A3, текст #10202A; тёмная тема по переключателю. Раскладка (боковая панель, рабочая область, выезжающая правая панель) по мотивам интерфейса AlexKlush/maieutica.

- **Последствия:** новые экраны собирать в этом же языке (плёнки, свет, форма линии как состояние); DESIGN.md будет записан по итогам сборки.

### 2026-10-03. Роли и главный демо-сценарий
- **Кто:** @LeshaKl (Алексей)
- **Статус:** принято
- **Контекст:** кто главный пользователь админки и что показываем жюри.
- **Решение:** в кабинете администратора переключатель ролей «Координатор / Врач». Кабинет пациента веб, на телефоне нижнее меню.
- **Почему / альтернативы:** «только B2B» и «только B2C» отклонены: кейс оценивает оба контура.
- **Последствия:** состояние записи общее для обоих кабинетов внутри прототипа.

### 2026-10-03. Публичная ссылка: Streamlit + Cloudflare quick tunnel
- **Кто:** @LeshaKl (Алексей)
- **Статус:** принято
- **Контекст:** нужна публичная ссылка на прототип в Streamlit прямо сейчас, без настройки серверов.
- **Решение:** Streamlit запускается локально на 8502 (`streamlit_app.py` встраивает весь `prototype/` одной страницей через `components.html`), наружу его выводит `cloudflared tunnel --url http://127.0.0.1:8502` (адрес `*.trycloudflare.com`, без аккаунта).
- **Почему / альтернативы:** Streamlit Community Cloud даёт постоянный адрес, но требует входа владельца репозитория через GitHub и доступа к приватному репо; ngrok требует аккаунт. Свой сервер (omni-server) занят другим проектом.
- **Последствия:** ссылка работает, пока Mac включён и оба процесса запущены; после перезапуска адрес меняется. Для постоянной ссылки — задеплоить на share.streamlit.io (`requirements.txt` и `.streamlit/config.toml` уже в репозитории). Внутри Streamlit страница живёт в iframe без истории браузера, поэтому маршрут прототипа хранится в памяти (см. `prototype/js/app.js`).
