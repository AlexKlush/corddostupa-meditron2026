# corddostupa-meditron2026

Этот файл читает Claude Code на любой машине при старте сессии. Общей памяти между компьютерами нет: **репозиторий и есть память проекта**. Если что-то важно знать следующей сессии (вашей или чужой), оно должно лежать здесь, в `docs/decisions.md` или в коде, а не только в чате.

## О проекте

Команда делает решение кейса компании «Третье мнение» на хакатоне **Meditron 2026**: сервис, который получает заключение ИИ по КТ, рентгенографии или маммографии (DICOM SR) и формирует пациенту персональный план дальнейшего обращения. Два контура: B2B (координатор или врач клиники видит, кому и куда предложить запись) и B2C (пациент видит понятный маршрут и записывается сам). Сервис не ставит диагноз, только навигирует.

- Условие кейса и выжимка из БФТ (поля Kafka, структура DICOM SR, шаблоны протоколов): `docs/case.md`.
- Продуктовый контекст для дизайна (пользователи, принципы, ограничения): `PRODUCT.md`.
- Текущий этап: кликабельный прототип интерфейсов на демо-данных (вымышленная клиника «Эгида»). Связь, шифрование, серверы пока не делаем (решение пользователя, см. `docs/decisions.md`).

### Как запустить прототип

- **Статическая версия:** `python3 scripts/serve.py` → http://localhost:8795. Это свой мини-сервер без кэша: обычный `python3 -m http.server` держит очередь всего из 5 соединений и рвёт параллельную загрузку файлов (страница тогда остаётся пустой).
- **Streamlit:** один раз `python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt`, затем `.venv/bin/streamlit run streamlit_app.py --server.port 8502` → http://localhost:8502. `streamlit_app.py` склеивает `prototype/` в одну страницу и показывает её на весь экран.
- **Публичная ссылка:** `cloudflared tunnel --url http://127.0.0.1:8502` печатает адрес `*.trycloudflare.com`. Ссылка живёт, пока на этом Mac работают Streamlit и cloudflared; после перезапуска адрес новый. Постоянный вариант: Streamlit Community Cloud (share.streamlit.io → New app → этот репозиторий, ветка `main`, файл `streamlit_app.py`), нужен вход владельца репозитория.
- **Структура:** `prototype/index.html`, `prototype/css/` (base, chooser, cabinet, admin, patient), `prototype/js/` (data — демо-данные, store — общее состояние двух кабинетов, admin/patient — кабинеты, engine — выноски, art — снимки и логотип), `prototype/vendor/lenis.min.js` (плавная прокрутка, MIT). Иконки — подмножество Lucide: дописать имя в `scripts/icons.txt` и пересобрать `scripts/gen_icons.js`.
- Дизайн-контекст: `PRODUCT.md` и контракт направления «Негатоскоп» в `.impeccable/surfaces/prototype-index-html.md`.

## Как мы работаем

Репозиторий: https://github.com/AlexKlush/corddostupa-meditron2026

Над проектом работают несколько человек с разных компьютеров и под **разными GitHub-аккаунтами**, у всех права write. Все коммитят в `main`. IP-адреса и машины значения не имеют: git смотрит только на аккаунт и права.

### В начале каждой сессии

1. `git pull --rebase --autostash origin main`: подтянуть чужую работу.
2. Прочитать этот файл и `docs/decisions.md`, особенно последние записи.
3. Посмотреть, что просили и что делали на других машинах: `git log --oneline -15` и `tail -n 80 $(ls -t docs/log/*.md | head -3)`. Так вторая сессия узнаёт контекст первой.

### Перед каждым пушем

```bash
git pull --rebase --autostash origin main
git push origin main
```

`--autostash` нужен потому, что hook (см. ниже) дописывает запрос в журнал при каждом сообщении, и в рабочей папке почти всегда есть незакоммиченный файл из `docs/log/`.

- **Никогда** `git push --force` / `--force-with-lease` в `main` и не переписывать опубликованную историю (`reset --hard` на опубликованных коммитах, `rebase` уже запушенного).
- Коммиты маленькие и частые: чем меньше коммит, тем легче разрешать конфликт.
- Если `pull --rebase` дал конфликт: разрешить, `git rebase --continue`, только потом пушить. Если непонятно, чья версия правильная, не выбирать наугад, а спросить пользователя.
- Крупное или рискованное изменение (рефакторинг, смена структуры, правка чужого модуля): отдельная ветка `имя/тема` и Pull Request, а не прямой пуш в `main`.
- Если два человека правят один файл одновременно, пользователям стоит договориться между собой. Claude должен предупредить, если видит свежие чужие коммиты в том же файле.

### Коммиты

- Сообщения коротко и по делу, в повелительном наклонении: `Add data loader`, `Fix tokenizer padding`.
- Автор коммита определяется `git config user.name/user.email` на конкретной машине. **Не менять чужие git-настройки** и не подписываться чужим именем.
- Не коммитить секреты, токены, `.env`, ключи, персональные и медицинские данные, большие файлы данных и веса моделей (см. `.gitignore`). Если нужно поделиться датасетом или весами, договориться о внешнем хранилище и записать ссылку в `docs/decisions.md`.

### Журнал решений

Любое неочевидное решение (выбор библиотеки, формат данных, отказ от подхода, договорённость между участниками) записывается в `docs/decisions.md` **в том же коммите**, что и изменение кода. Формат записи описан в начале файла. Записи только добавляются в конец; старые не переписываются, а отменяются новой записью. Конфликт при одновременном добавлении записей решается просто: оставить обе.

### Журнал запросов (`docs/log/`)

Чтобы сохранялись **все просьбы с каждой машины и что по ним изменено**:

- Hook `scripts/log_prompt.py` (подключён в `.claude/settings.json`, событие `UserPromptSubmit`) **автоматически** дописывает каждое сообщение пользователя дословно в `docs/log/ГГГГ-ММ-ДД_<git-user>_<машина>.md`. Один файл на человека, машину и день, поэтому две машины никогда не правят один и тот же файл и конфликтов не будет. Токены вида `ghp_`, `sk-`, `AKIA` и приватные ключи маскируются.
- Когда Claude закончил задачу, он **дописывает под последним запросом** в своём файле журнала строку `**Сделано:** ...`: что именно изменено (файлы, коммит), какие решения приняты (ссылка на запись в `decisions.md`), что осталось недоделанным. Если запрос был только вопросом, достаточно «Сделано: ответил на вопрос».
- Файл журнала коммитится **вместе с работой**: `git add docs/log` в том же коммите. Чужие файлы в `docs/log/` не редактировать и не удалять.
- Если hook не сработал (например, нет `python3`), Claude вручную добавляет запрос в журнал по тому же формату.
- Запросы пишутся дословно, поэтому **не вставлять в чат секреты, пароли и чужие персональные данные**. Репозиторий должен оставаться **приватным**; если его делают публичным, сначала удалить `.claude/settings.json` и `docs/log/`.
- При первом открытии проекта на новой машине Claude Code спросит доверие к hook-у проекта. Скрипт короткий, его можно прочитать перед подтверждением. Нужен `python3`.

### Что Claude делает сам, а что спрашивает

- Сам: читает, ищет, запускает тесты, делает локальные коммиты, `pull --rebase`.
- Спрашивает перед: пушем в `main`, если в `git log` есть чужие свежие коммиты в тех же файлах; удалением файлов, которые не создавал; любым действием, которое трудно откатить.
- Если в репозитории найдено расхождение между этим файлом и реальностью (устаревшая команда, переименованная папка), исправить файл в том же коммите.

## Личные настройки

Всё, что относится только к одной машине или одному человеку, не коммитится: `CLAUDE.local.md`, `.claude/settings.local.json` (оба в `.gitignore`). Общий `.claude/settings.json` (hook журнала) коммитится.
