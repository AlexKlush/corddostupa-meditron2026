## Как мы работаем

Репозиторий: https://github.com/AlexKlush/corddostupa-meditron2026

Над проектом работают несколько человек с разных компьютеров и под **разными GitHub-аккаунтами**, у всех права write. Все коммитят в `main`. IP-адреса и машины значения не имеют: git смотрит только на аккаунт и права.

### В начале каждой сессии

1. `git pull --rebase origin main`: подтянуть чужую работу.
2. Прочитать этот файл и `docs/decisions.md`, особенно последние записи.
3. `git log --oneline -15`: посмотреть, что менялось с прошлого раза.

### Перед каждым пушем

```bash
git pull --rebase origin main
git push origin main
```

- **Никогда** `git push --force` / `--force-with-lease` в `main` и не переписывать опубликованную историю (`reset --hard` на опубликованных коммитах, `rebase` уже запушенного).
- Коммиты маленькие и частые: чем меньше коммит, тем легче разрешать конфликт.
- Если `pull --rebase` дал конфликт: разрешить, `git rebase --continue`, только потом пушить. Если непонятно, чья версия правильная, не выбирать наугад, а спросить пользователя.
- Крупное или рискованное изменение (рефакторинг, смена структуры, правка чужого модуля): отдельная ветка `имя/тема` и Pull Request, а не прямой пуш в `main`.
- Если два человека правят один файл одновременно, пользователям стоит договориться между собой. Claude должен предупредить, если видит свежие чужие коммиты в том же файле.

### Коммиты

- Сообщения коротко и по делу, в повелительном наклонении: `Add data loader`, `Fix tokenizer padding`.
- Автор коммита определяется `git config user.name/user.email` на конкретной машине. **Не менять чужие git-настройки** и не подписываться чужим именем.
- Не коммитить секреты, токены, `.env`, ключи, персональные и медицинские данные, большие файлы данных и веса моделей (см. `.gitignore`). Если нужно поделиться датасетом или весами, договориться о внешнем хранилище и записать ссылку в `docs/decisions.md`.

### Журнал решений

Любое неочевидное решение (выбор библиотеки, формат данных, отказ от подхода, договорённость между участниками) записывается в `docs/decisions.md` **в том же коммите**, что и изменение кода. Формат записи описан в начале файла. Записи только добавляются в конец; старые не переписываются, а отменяются новой записью. Конфликт при одновременном добавлении записей решается просто: оставить обе.

### Что Claude делает сам, а что спрашивает

- Сам: читает, ищет, запускает тесты, делает локальные коммиты, `pull --rebase`.
- Спрашивает перед: пушем в `main`, если в `git log` есть чужие свежие коммиты в тех же файлах; удалением файлов, которые не создавал; любым действием, которое трудно откатить.
- Если в репозитории найдено расхождение между этим файлом и реальностью (устаревшая команда, переименованная папка), исправить файл в том же коммите.

## Личные настройки

Всё, что относится только к одной машине или одному человеку, не коммитится: `CLAUDE.local.md`, `.claude/settings.local.json` (оба в `.gitignore`).
